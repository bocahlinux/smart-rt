# Smart-RT — Database Design Document

**Version:** 1.3.0
**Date:** June 8, 2026
**Database:** PostgreSQL 16
**ORM:** Django ORM (bawaan)
**Status:** Draft

---

## 1. Database Overview

### 1.1 Why PostgreSQL
- **ACID compliant** — Transaksi keuangan butuh konsistensi data
- **JSON support** — Fleksibel untuk metadata & opsi polling (JSONField)
- **Full-text search** — Pencarian warga tanpa dependency eksternal
- **Free & open source** — Cocok untuk komunitas
- **Django ORM support** — First-class support untuk PostgreSQL

### 1.2 Database Configuration
```env
DATABASE_URL="postgresql://smartrt:***@localhost:5432/smartrt"
```

### 1.3 Naming Conventions
- Table names: auto-generated by Django (e.g., `app_modelname`)
- Column names: `snake_case` (e.g., `nama_lengkap`)
- Primary key: `id` (UUID, generated via `uuid.uuid4`)
- Foreign keys: `{table}_id` (e.g., `user_id`)
- Timestamps: `created_at`, `updated_at`
- Indexes: `idx_{table}_{column}`

- **User** → **WargaProfile** (1:1, optional — hanya untuk role warga)
- **User** → **Transaksi** (1:N, sebagai created_by)

- **Thread** → **Comments** (1:N)
- **Poll** → **Votes** (1:N)
- **Kegiatan** → **RSVP** (1:N)

## 3. Data Classification

Semua data dalam sistem Smart-RT diklasifikasikan ke dalam 4 tingkat:

### 3.1 Public
Data yang boleh dilihat oleh semua role (termasuk warga):

| Data | Lokasi |
|------|--------|
| Nama kegiatan | `kegiatan.nama` |
| Deskripsi kegiatan | `kegiatan.deskripsi` |
| Pengumuman publik | `pengumuman.judul`, `pengumuman.isi` |
| Thread forum (non-sensitif) | `threads.judul`, `comments.isi` |
| Polling pertanyaan & hasil agregat | `polls.pertanyaan` |

### 3.2 Internal
Data untuk internal RT, tidak di-expose ke publik:

| Data | Lokasi |
|------|--------|
| Forum internal RT | `threads` dengan kategori internal |
| Status iuran agregat (total lunas/belum) | `iuran_warga.status` (agregat) |
| Statistik dashboard | Computed dari berbagai tabel |

### 3.3 Sensitive
Data pribadi warga, akses terbatas berdasarkan role dan object-level permission:

| Data | Lokasi | Aturan Akses |
|------|--------|-------------|
| NIK | `warga_profiles.nik` | Pemilik, sekretaris, admin (full). Bendahara, pengurus (masked). Warga lain (hidden). |
| No. KK | `warga_profiles.no_kk` | Pemilik, sekretaris, admin (full). Bendahara, pengurus (masked). Warga lain (hidden). |
| Alamat lengkap | `warga_profiles.alamat` | Pemilik, sekretaris, admin. Others (hidden). |
| Tanggal lahir | `warga_profiles.tanggal_lahir` | Pemilik, sekretaris, admin. Others (hidden). |
| Nomor HP | `users.phone` | Pemilik, sekretaris, bendahara, admin (full). Pengurus, warga lain (masked/hidden). |
| Email | `users.email` | Pemilik, sekretaris, admin. Others (hidden). |
| Foto profil | `warga_profiles.foto` | Pemilik, sekretaris, bendahara, admin. Pengurus (masked). Warga lain (hidden). |
| Bukti transfer | `transaksi.bukti_url`, `iuran_warga.bukti_url` | Pemilik transaksi, bendahara, admin. Others (hidden). |
| Data pengaduan | `pengaduan.*` | Pelapor, sekretaris, pengurus berwenang, admin. Pengaduan sensitif: tidak publik. |

### 3.4 Restricted
Data sistem, tidak boleh di-expose ke mana pun kecuali ke sistem itu sendiri:

| Data | Lokasi | Aturan |
|------|--------|--------|
| Password hash | `users.password` | Never exposed. Django hashed (Argon2/PBKDF2). |
| Token / JWT secret | Environment variable | Never in database or code. |
| Audit log detail | `audit_logs.*` | Hanya admin. Tidak menyimpan data sensitif mentah. |
| Backup database | File system / cloud | Terenkripsi. Akses terbatas. |
| Secret key / credential | Environment variable | Never in code or database. |

| Column | Type | Constraints | Classification | Description |
|--------|------|-------------|----------------|-------------|
| id | UUID | PK, DEFAULT uuid4 | — | |
| user_id | UUID | FK → users.id | — | User yang melakukan aksi |
| action | VARCHAR(50) | NOT NULL | — | create/update/delete/verify/view |
| table_name | VARCHAR(50) | NOT NULL | — | Nama tabel yang diubah |
| record_id | INT | NOT NULL | — | ID record yang diubah |
| old_data | JSON | NULLABLE | **Restricted** | Data sebelum perubahan (field sensitif di-mask) |
| new_data | JSON | NULLABLE | **Restricted** | Data sesudah perubahan (field sensitif di-mask) |
| created_at | TIMESTAMP | DEFAULT now() | — | |

**Indexes:**
- `idx_audit_user` ON (user_id)
- `idx_audit_table` ON (table_name)
- `idx_audit_created` ON (created_at)

**⚠️ Audit Log Data Policy:**
- **Dilarang** menyimpan password, token, secret, atau file content di `old_data`/`new_data`.
- Field sensitif (NIK, no KK, no HP, email, alamat) harus di-mask atau di-redact di `old_data`/`new_data`.
- Contoh masking: NIK `3201010101010001` → `3201********0001`.
- Audit log hanya boleh diakses oleh admin.

import uuid

from django.contrib.auth.models import AbstractUser
from django.db import models

class User(AbstractUser):
    """Extended User model dengan role-based access"""
    id = models.UUIDField(primary_key=True, default=uuid.uuid4, editable=False)
    
    class Role(models.TextChoices):
        ADMIN = 'admin', 'Admin'
        SEKRETARIS = 'sekretaris', 'Sekretaris'
        BENDAHARA = 'bendahara', 'Bendahara'
        PENGURUS = 'pengurus', 'Pengurus'
        WARGA = 'warga', 'Warga'
    
    class Status(models.TextChoices):
        PENDING = 'pending', 'Pending'
        ACTIVE = 'active', 'Active'
        REJECTED = 'rejected', 'Rejected'
    
    email = models.EmailField(unique=True)
    phone = models.CharField(max_length=20, unique=True)
    role = models.CharField(max_length=20, choices=Role.choices, default=Role.WARGA)
    status = models.CharField(max_length=20, choices=Status.choices, default=Status.PENDING)
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
    
    # Disable default username, use email instead
    USERNAME_FIELD = 'email'
    REQUIRED_FIELDS = ['username', 'phone']
    
    class Meta:
        db_table = 'users'
        indexes = [
            models.Index(fields=['email'], name='idx_users_email'),
            models.Index(fields=['phone'], name='idx_users_phone'),
            models.Index(fields=['role'], name='idx_users_role'),
            models.Index(fields=['status'], name='idx_users_status'),
        ]
    
    def __str__(self):
        return self.email


class WargaProfile(models.Model):
    """Profil lengkap warga — data SENSITIF"""
    id = models.UUIDField(primary_key=True, default=uuid.uuid4, editable=False)

    class JenisKelamin(models.TextChoices):
        LAKI = 'L', 'Laki-laki'
        PEREMPUAN = 'P', 'Perempuan'
    
    class StatusPerkawinan(models.TextChoices):
        BELUM_KAWIN = 'belum_kawin', 'Belum Kawin'
        KAWIN = 'kawin', 'Kawin'
        CERAI_HIDUP = 'cerai_hidup', 'Cerai Hidup'
        CERAI_MATI = 'cerai_mati', 'Cerai Mati'
    
    class Status(models.TextChoices):
        AKTIF = 'aktif', 'Aktif'
        TIDAK_AKTIF = 'tidak_aktif', 'Tidak Aktif'
        PINDAH = 'pindah', 'Pindah'
        MENINGGAL = 'meninggal', 'Meninggal'
    
    user = models.OneToOneField(User, on_delete=models.CASCADE, related_name='profile')
    nik = models.CharField(max_length=16, unique=True, null=True, blank=True)  # SENSITIF
    nama_lengkap = models.CharField(max_length=255)
    tempat_lahir = models.CharField(max_length=100, null=True, blank=True)  # SENSITIF
    tanggal_lahir = models.DateField(null=True, blank=True)  # SENSITIF
    jenis_kelamin = models.CharField(max_length=1, choices=JenisKelamin.choices, null=True, blank=True)
    agama = models.CharField(max_length=50, null=True, blank=True)
    status_perkawinan = models.CharField(max_length=20, choices=StatusPerkawinan.choices, null=True, blank=True)
    pendidikan = models.CharField(max_length=100, null=True, blank=True)
    pekerjaan = models.CharField(max_length=100, null=True, blank=True)
    no_kk = models.CharField(max_length=16, null=True, blank=True)  # SENSITIF
    hubungan_keluarga = models.CharField(max_length=50, null=True, blank=True)

    no_rumah = models.CharField(max_length=10, null=True, blank=True)
    status = models.CharField(max_length=20, choices=Status.choices, default=Status.AKTIF)
    foto = models.FileField(upload_to='foto-profil/', null=True, blank=True)  # SENSITIF
    is_deleted = models.BooleanField(default=False)
    deleted_at = models.DateTimeField(null=True, blank=True)
    deleted_by = models.ForeignKey(User, on_delete=models.SET_NULL, null=True, blank=True, related_name='warga_deleted')
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)

    class Meta:
        db_table = 'warga_profiles'
        indexes = [
            models.Index(fields=['nama_lengkap'], name='idx_warga_nama'),
            models.Index(fields=['blok'], name='idx_warga_blok'),
            models.Index(fields=['status'], name='idx_warga_status'),
            models.Index(fields=['nik'], name='idx_warga_nik'),

class Transaksi(models.Model):
    """Data keuangan — SENSITIF"""
    id = models.UUIDField(primary_key=True, default=uuid.uuid4, editable=False)

    class Tipe(models.TextChoices):
        PEMASUKAN = 'pemasukan', 'Pemasukan'
        PENGELUARAN = 'pengeluaran', 'Pengeluaran'
    
    class Status(models.TextChoices):
        PENDING = 'pending', 'Pending'
        CONFIRMED = 'confirmed', 'Confirmed'
        REJECTED = 'rejected', 'Rejected'
    
    kategori = models.ForeignKey(KategoriTransaksi, on_delete=models.PROTECT)

    keterangan = models.TextField(null=True, blank=True)
    tanggal = models.DateField()
    tipe = models.CharField(max_length=20, choices=Tipe.choices)
    status = models.CharField(max_length=20, choices=Status.choices, default=Status.CONFIRMED)
    bukti_url = models.FileField(upload_to='bukti-transfer/', null=True, blank=True)  # SENSITIF
    created_by = models.ForeignKey(User, on_delete=models.PROTECT, related_name='transaksi_created')
    confirmed_by = models.ForeignKey(User, on_delete=models.SET_NULL, null=True, blank=True, related_name='transaksi_confirmed')
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
    
    class Meta:
        db_table = 'transaksi'
        indexes = [
            models.Index(fields=['tanggal'], name='idx_transaksi_tanggal'),
            models.Index(fields=['tipe'], name='idx_transaksi_tipe'),
            models.Index(fields=['status'], name='idx_transaksi_status'),
        ]

## 6. Encryption & Hashing Policy

### 6.1 Password Hashing
- **Algoritma:** Django default password hasher (Argon2).
- **Fallback:** PBKDF2 dengan SHA256 (Django default sebelum Argon2).
- **Konfigurasi di `settings.py`:**
```python
PASSWORD_HASHERS = [
    'django.contrib.auth.hashers.Argon2PasswordHasher',
    'django.contrib.auth.hashers.PBKDF2PasswordHasher',
    'django.contrib.auth.hashers.PBKDF2SHA1PasswordHasher',
]
```
- **Dilarang** menggunakan MD5, SHA1, atau plain text.

### 6.2 Field-Level Encryption (MVP vs Production)

**MVP (Recommended untuk memulai):**
- Tidak encrypt field sensitif di database.
- Fokus pada: RBAC, object-level permission, masking di UI, audit log, backup encrypted.
- Alasan: lebih simpel, performa lebih baik, mudah debug.

**Production Hardening (jika diperlukan):**
- Encrypt field paling sensitif: NIK, no KK, alamat, nomor HP.
- Gunakan `django-encrypted-model-fields` atau `django-fernet-fields`.
- Key enkripsi disimpan di environment variable.
- Trade-off: tidak bisa search/filter by field yang di-encrypt.

### 6.3 JWT Signing Key
- Disimpan di environment variable (`JWT_SECRET_KEY` atau `SECRET_KEY` Django).
- Minimum 256-bit.
- **Dilarang** hardcode di source code.

### 6.4 File Upload
- File disimpan dengan nama random (UUID), bukan original filename.
- Validasi MIME type (magic bytes), bukan cuma extension.
- Max file size: 5MB.
- Simpan di dedicated upload path, bukan executable directory.
- Serve via Django `FileField` / `django-storages` (S3 compatible).

## 9. Backup & Recovery

### 9.1 Automated Backup (Daily) — **Encrypted**

```bash
# Cron job: setiap jam 2 pagi
# Backup dengan GPG encryption (AES256)
0 2 * * * pg_dump -U smartrt smartrt | gzip | gpg --symmetric --cipher-algo AES256 --passphrase-file /root/.backup_key -o /backup/smartrt_$(date +\%Y\%m\%d).sql.gz.gpg

# Alternatif: gpg dengan key-based encryption (lebih aman)
0 2 * * * pg_dump -U smartrt smartrt | gzip | gpg --encrypt --recipient backup@smartrt.local -o /backup/smartrt_$(date +\%Y\%m\%d).sql.gz.gpg
```

**⚠️ Penting:**
- Gzip saja **bukan enkripsi** — hanya kompresi. Siapa pun bisa decompress.
- Backup **wajib** di-encrypt dengan GPG (AES256) atau server-side encryption jika pakai cloud storage.
- Backup key/passphrase disimpan terpisah dari backup file.
- Akses ke backup file dibatasi (file permission `600`).

### 9.2 Django Backup Command
```bash
# Dump data
python manage.py dumpdata --natural-foreign --indent 2 > backup.json

# Load data
python manage.py loaddata backup.json
```

### 9.3 Retention Policy
- Daily backup: simpan 30 hari
- Weekly backup: simpan 12 minggu
- Monthly backup: simpan 12 bulan

### 9.4 Backup Access Control
- Backup file permission: `600` (owner read/write only).
- Backup directory: terpisah dari application directory.
- Cloud storage (jika pakai): server-side encryption + IAM restricted access.
- **Dilarang** menyimpan backup di repository Git.

## 10. Data Protection Policy

### 10.1 Data Minimization
- Hanya kumpulkan data yang benar-benar diperlukan.
- Field opsional tidak wajib diisi saat registrasi.

### 10.2 Least Privilege Access
- Setiap role hanya bisa akses data yang sesuai perannya.
- Object-level permission untuk data spesifik (lihat SDD §4.3).

### 10.3 Masking Data Sensitif
- NIK: `3201********0001`
- No KK: `3201********5678`
- No HP: `0812****5678`
- Email: `ah***@gmail.com`
- Masking diterapkan di API response dan UI untuk role yang tidak berhak.

### 10.4 Auditability
- Semua akses dan perubahan data sensitif tercatat di `audit_logs`.
- Audit log tidak menyimpan data sensitif mentah (harus di-mask/redact).
- Audit log hanya bisa diakses oleh admin.

### 10.5 User Consent
- Warga harus memberikan persetujuan saat mendaftar untuk pengelolaan data pribadi.
- Teks consent disertakan di halaman registrasi.

### 10.6 Data Retention
- Data warga yang statusnya `pindah` atau `meninggal` di-soft delete, bukan hard delete.
- Mekanisme soft-delete pada `WargaProfile`: field `is_deleted` (default `False`), `deleted_at` (timestamp saat dihapus), dan `deleted_by` (FK ke `User` admin yang melakukan penghapusan).
- Saat soft-delete dijalankan: set `is_deleted=True`, `deleted_at=now()`, `deleted_by=<admin>`. Data tidak dihapus dari database — hanya disembunyikan dari query default (`get_queryset` wajib filter `is_deleted=False` kecuali untuk Admin yang membuka arsip).
- Data soft-deleted disimpan maksimal 2 tahun (dihitung sejak `deleted_at`), kemudian dihapus permanen (hard delete) via scheduled job.
- Backup terenkripsi disimpan sesuai retention policy (§9.3).

### 10.7 Right to Access & Deletion
- Warga bisa mengunduh data pribadinya sendiri (export profil).
- Warga bisa meminta penghapusan data (sesuai regulasi yang berlaku).
- Proses penghapusan data memerlukan verifikasi admin.

## 11. Performance Considerations

### 11.1 Indexing Strategy
- **Primary keys**: UUID (`uuid.uuid4`) untuk mengurangi risiko ID enumeration pada API
- **Foreign keys**: Django auto-indexes FK fields
- **Search fields**: `nama_lengkap`, `email`, `phone`, `nik`
- **Filter fields**: `status`, `role`, `kategori`, `tipe`
- **Composite indexes**: Unique together untuk mencegah duplikat

# Use select_related for FK (JOIN)
warga = WargaProfile.objects.select_related('user').all()

threads = Thread.objects.prefetch_related('comments').all()

# Use only/defer untuk ambil kolom tertentu
users = User.objects.only('id', 'email', 'role')

emails = User.objects.values_list('email', flat=True)
